EXPLICACION DE CONEXION SUPABASE (ERROR ENOTFOUND / CHAT EN NEGRO)

Hola, he creado este archivo porque mencionas que el chat se ve en negro.

1. ¿POR QUE EL ERROR ENOTFOUND?
La cadena de conexion directa (db.djpdkfxagmmbyjwqcxzf.supabase.co:5432) 
ahora es EXCLUSIVA PARA IPv6 en Supabase. Si tu red/PC local no tiene IPv6, 
no puede resolver el host y da el error "getaddrinfo ENOTFOUND".

2. ¿COMO SOLUCIONARLO?
Debes usar el "Connection Pooler" de Supabase, que si soporta IPv4.

Sigue estos pasos:
- Ve a tu Dashboard de Supabase -> Settings (icono de engranaje) -> Database.
- Busca la seccion "Connection Pooler" (justo al lado o abajo de Direct Connection).
- Selecciona el modo "Transaction" o "Session".
- Copia la cadena de conexion (URI) que te da. Tendra un formato como:
  postgresql://postgres.djpdkfxagmmbyjwqcxzf:[TU-PASSWORD]@aws-0-[region].pooler.supabase.com:6543/postgres

- Modifica tu archivo .env con esos datos:
  DB_HOST = aws-0-[region].pooler.supabase.com (ej. aws-0-us-west-1.pooler.supabase.com)
  DB_PORT = 6543
  DB_USER = postgres.djpdkfxagmmbyjwqcxzf
  DB_PASSWORD = [Tu contraseña]

3. REINICIAR LA API:
Una vez que guardes el archivo .env con los nuevos datos, detén el servidor
en la terminal (Ctrl + C) y vuelve a ejecutar:
  pnpm run start

4. ¿HACE FALTA LA CONNECTION STRING?
No. La aplicacion esta configurada para leer las variables individuales (DB_HOST, DB_PORT, etc.) desde tu archivo .env. No necesitas definir una variable DATABASE_URL unica.

5. ESTADO ACTUAL:
¡La conexion funciona! He realizado una prueba y el servidor responde correctamente. Ya puedes probarla con Postman o tu cliente REST.

8. ¿POR QUE EL ERROR "CREDENCIALES INVALIDAS" (401)?
¡Buenas noticias! Este error indica que el servidor YA se conecta exitosamente a tu base de datos en Supabase. Ahora es un error de usuario/contraseña.

Asegurate de enviar exactamente estos datos en el Body de Postman (tipo raw JSON):

Usuario 1:
{
  "email": "usuario1@mail.com",
  "password": "password123"
}

Usuario 2:
{
  "email": "usuario2@mail.com",
  "password": "password456"
}

Administrador:
{
  "email": "admin@mail.com",
  "password": "admin789"
}

9. ERROR AL CREAR TAREA (PROPERTY NOMBRE SHOULD NOT EXIST...):
- Este error ocurre porque enviaste la peticion a la URL incorrecta en Postman.
- La respuesta pide "email" y "contraseña" (que son del Login), lo que significa que hiciste el POST a la URL:
    http://localhost:3000/auth/login
  en lugar de:
    http://localhost:3000/tasks

¿COMO SOLUCIONARLO?
- Cambia la URL en Postman a: http://localhost:3000/tasks
- Asegúrate de que el metodo sea POST.
- Mantén la pestaña Authorization configurada con el Bearer Token.


10. GUIA PARA PROBAR EL RESTO DE ENDPOINTS EN POSTMAN:
Recuerda configurar en todos la pestaña "Authorization" -> "Bearer Token".

---
A) OBTENER LISTA DE TAREAS (GET)
- URL: http://localhost:3000/tasks
- Query Params opcionales (puedes agregarlos en Params):
  * estado = pendiente
  * asignado_a = 2
  * search = Postman

---
B) VER DETALLE DE TAREA (GET)
- URL: http://localhost:3000/tasks/1/details
  (Reemplaza "1" por el ID de la tarea que creaste).

---
C) MODIFICAR TAREA (PATCH)
- URL: http://localhost:3000/tasks/1
- Body (raw JSON):
  {
    "estado": "en progreso",
    "story_points": 8
  }

---
D) CREAR COMENTARIO (POST)
- URL: http://localhost:3000/comments
- Body (raw JSON):
{
  "contenido": "Este es un comentario de prueba",
  "tarea_id": 1
}

---
E) ASOCIAR CATEGORIA EXISTENTE A TAREA (POST)
- URL: http://localhost:3000/tasks/1/categories/2
  (Asocia la tarea ID 1 con la categoria ID 2. Las categorías iniciales son Bug=1, Feature=2, Mejora=3, Documentación=4).

---
F) CREAR Y ASOCIAR NUEVA CATEGORIA (POST)
- URL: http://localhost:3000/tasks/1/categories
- Body (raw JSON):
{
  "nombre": "Urgente",
  "descripcion": "Tareas criticas",
  "color": "#FF0000"
}

---
G) ELIMINAR CATEGORIA (DELETE)
- URL: http://localhost:3000/categories/1

---
H) LOGOUT / REVOCAR TOKEN (POST)
- URL: http://localhost:3000/auth/logout


11. ERROR EN POSTMAN: "base_url: expected undefined to be a string"
Este error indica que Postman NO esta enviando la peticion porque fallo un script previo (Pre-request Script) que espera una variable.

¿COMO SOLUCIONARLO?
1. En Postman, ve a las variables de tu Coleccion (Collection) o de tu Entorno (Environment).
2. Agrega la variable "base_url" con el valor: http://localhost:3000
3. Si no usas variables, ve a la pestaña "Pre-request Script" (en la coleccion o en la peticion) y borra o comenta las lineas que validan "base_url" (el AssertionError).
